ПРАКТИЧНІ НОТАТКИ / ОЛЕГ ГЕБЕЛЬ

Що потрібно дизайн-системі для AI-агентів

Агент має отримати правильне правило раніше, ніж створить правдоподібну заміну.

Джерела + правила + пошук + перевірка

Більшість зрілих систем створені для людей: дизайнер переглядає Figma, інженер — Storybook, а причину рішення можна уточнити в колеги. AI-агенту потрібен той самий продуктовий контекст у доступній формі.

Наявності компонентів недостатньо. Між існуванням правила та його застосуванням потрібен операційний рівень: канонічне джерело, коротка інструкція, доречний контекст і спосіб перевірити результат.

1 / Визнач джерело істини

Якщо Figma, Storybook і CSS суперечать одне одному, агент не може усунути організаційну неоднозначність. Визнач авторитет за категоріями: версійовані токени для кольору, шрифту та відступів; реальна бібліотека для API компонентів; правило й приклад для взаємодії; короткі нотатки для продуктових компромісів.

Код показує, що реалізовано, але не завжди пояснює, чому патерн став стандартом. Зберігай прийняті рішення поруч із продуктом.

2 / Записуй обмеження, а не побажання

«Зроби чисто» — вподобання. «Використай наявний Dialog; новий примітив потребує окремої потреби взаємодії» — правило. Хороша інструкція відповідає: що повторно використати, що можна змінити, де приклад і як перевірити відповідність.

Інструкції репозиторію та спеціальні правила інструментів мають посилатися на систему, а не існувати окремо від неї.

3 / Завантажуй потрібний контекст у потрібний момент

Постійний шар: невеликі глобальні правила, бібліотека, токени, адаптивність, доступність. Шар за ділянкою продукту: форми, таблиці, мобільні сценарії. Довідка за потреби: API, приклади, зображення й обґрунтування. Поточна задача: макет, issue, історія користувача або обмеження сценарію.

Величезний довідник не гарантує корисного контексту. Агенту потрібна інформація, доречна саме зараз, без застарілих і суперечливих копій.

4 / Додай друге визначення готовності

Функціональна перевірка запитує, чи компілюється код і чи завершується дія. Системна — чи з’явилися довільні значення, дублікати, інші стани помилок або порушена мобільна ієрархія.

Перші п’ять артефактів: семантична мапа токенів, реєстр компонентів зі статусом, правила патернів, файли контексту для агентів і легка перевірка відповідності.

Рівні зрілості

0 / Знання в людях: агент вигадує. 1 / Документація: агент може її пропустити. 2 / Канонічність: джерела визначені, ними можна користуватися за посиланням. 3 / Контекст: правила доступні відповідно до задачі. 4 / Перевірка: зміни досліджують до завершення.

Не кожній ділянці потрібен максимальний рівень. Почни там, де швидкість AI-розробки створює найбільше повторної роботи. Хороша система зменшує необхідність знову пояснювати продукт.
